# Single- and Dual-Perspective Protocol

本协议决定信息来源和结论上限。任何模式都不承诺“查明绝对真相”；目标是得到当前证据下最公平、最可检验的解释。

## Mode selection

在整段关系健康度、长期责任、是否继续/复合的评估开始时，明确选择：

- **S — 单视角**：只有一方作答。可立即评估，但结论写成条件式，不能冒充双方共识。
- **D — 双视角**：两名相关当事人独立完成同一份镜像信息包，再合并比较。默认推荐，前提是双方自愿且没有披露后报复风险。
- **M — 多视角**：争议直接涉及三名或更多关系参与者时，各相关当事人独立完成同题；只比较与争议有关的关系边，不强迫所有人评价所有人。
- **R — 记录增强**：在 S、D 或 M 上加入已脱敏、上下文相对完整的聊天或约定记录。

若用户未选，信息包第一项即为模式选择。只有一方参与时不拖延服务，直接使用 S。

## Shared definitions

两人争议固定角色为 A、B；多人争议使用 P1、P2、P3……。不用“男/女”“理性/感性”或“提问者/被告”。固定同一时间窗，推荐最近 3 个月；关系更短则用完整关系期，已分手则用分手前最后 3 个月。

频率量尺：

`0 没有 | 1 一次 | 2 偶尔 | 3 多次 | 4 大多数相关情境 | N 不适用/无观察机会 | U 不确定`

`0` 表示有观察机会但没有发生；`N` 表示没有相关场景或无法观察；`U` 表示存在场景但作答者不能确定。三者不得混算。

每个核心领域必须使用同一措辞评价 A 与 B；严重行为另外记录具体事件，不能靠频率平均。

## Core mirrored domains

正式测试的具体20/40题行为锚定题库见 [objective-items.md](objective-items.md)。以下十项是领域概览，不应在用户要求全面测试时替代详细题库。

1. **尊重**：辱骂、讽刺、人格贬低、公开羞辱。
2. **自主与同意**：能否自由拒绝查看手机、定位、性行为、金钱或社交要求而不受惩罚。
3. **冲突升级**：吼叫、威胁、砸物、堵门、报复或持续逼迫。
4. **暂停与回流**：需要冷静时是否说明时长并按约恢复；是否追堵或惩罚性消失。
5. **诚实与约定**：是否隐瞒关键事实、反复失约且不重新协商。
6. **倾听与责任**：能否准确复述对方关切、承认自己的具体行为，而非只反击动机。
7. **修复与改变**：是否有具体道歉、补救、可观察改变及维持时间。
8. **互惠与负担**：时间、金钱、家务、照护和情绪劳动是否按约定分配并可重新协商。
9. **支持与善意**：普通时期是否存在可靠支持、欣赏、关心和正向互动。
10. **目标兼容**：双方最低条件是否明确、自愿且能同时满足。

这些领域是结构化比较框架，不是标准化心理量表。可以按 [quantitative-output.md](quantitative-output.md) 转换为来源分开的描述性指数，但不得称为科学分数，也不得自动生成主责。

## S — Single-perspective test

让作答者在一条消息中提供：

1. 对 A、B 使用完全相同的核心领域频率评价；
2. 一个对自己不利、一个对对方不利的具体事件，均按触发→双方行为→结果→修复描述；
3. 双方明确说过的需求、边界和最低目标；
4. 已有改变记录与一个反证；
5. 必要安全信息。

分析时同时生成：

- **按叙述成立时的行为判断**；
- **可能受单方视角影响的部分**；
- **一个不新增事实的对方版本**；
- **最能区分两个版本的新证据**。

结论上限：可以明确评价已描述行为和当前决策风险；除非有强记录或多事件一致证据，不声称确认对方动机、全部频率或双方共同事实。

## D — Dual-perspective test

### Independence

双方必须独立作答同一题面、同一时间窗和同一量尺。推荐做法：把空白表分别发给 A、B，在两人都完成前不展示另一方答案；随后将两份标记为 `[A独立回答]`、`[B独立回答]` 的内容一起提交。

若只能在同一对话轮流回答，明确说明后一方已可能受前一方框架影响，因此独立性较弱。分歧不等于撒谎，一致也不自动等于事实；记忆、理解和自我呈现都可能影响报告。

### Each partner answers

每人都回答：

1. 自己在十个领域的频率；
2. 观察到对方在同样十个领域的频率；
3. 自己选择的一个代表事件；
4. 自己最需要改变的一项与希望对方改变的一项；
5. 最支持和最不支持自己当前看法的事实；
6. 最低条件、愿意投入的改变和停止条件。

安全筛查应允许各自私下完成。若一方害怕另一方看到答案、存在强迫控制或可能报复，停止联合模式，不要求共享回答，转入安全路径。

### Cross-source matrix

对每个领域比较四个信息点：

```text
A自评 | B对A的评价 | B自评 | A对B的评价
```

再与具体事件和记录核验。不得只平均四个数字。按以下方式编码：

- **交叉一致**：自评与对方评价接近，且事件支持；
- **部分一致**：行为存在一致，但频率/严重度不同；
- **视角分歧**：自评与对方评价明显冲突；
- **事实冲突**：对同一时间、原话或动作的陈述不能同时成立；
- **未知**：缺乏足够具体材料。

视角分歧本身是关系信息，常提示定义不一致、影响未被看见、防御、记忆差异或信任破裂；它不是自动的责任分。

## R — Records-enhanced test

记录只用于核验具体原话、时间、约定和后续，不用于读取未提供的动机。要求先隐去身份、账号、地址、单位、联系方式和私密影像。

检查：

- 是否有冲突前后文，而非只截最有利片段；
- 是否双方选择机会大致对等；
- 记录能证明什么、不能证明什么；
- 口头模式是否跨多个日期重复；
- 是否存在通过“要求交证据”实施监控或控制的风险。

## M — Multi-perspective adaptation

多人关系不把问题强行压缩成虚假的 A/B 对立：

- 先确定哪些人直接参与本次争议、共同协议适用于谁；
- 每位相关参与者独立回答 D 模式的相同题面；
- 对每一条相关关系边比较 `Pᵢ自评 / 其他相关方对Pᵢ的观察 / 具体事件 / 记录`；
- 区分个人行为、两人互动、群体协议和整体结构压力；
- 不以多数票决定事实或道德责任，也不要求无关参与者披露私人信息；
- 若只有一人愿意作答，降级为 S 模式；拒绝参与本身不是有责证据。

## Best-supported mechanism, not “absolute essence”

最终把“本质问题”写成当前证据最支持的机制模型：

1. **表面议题**：手机、回复、家务、金钱、婚育等。
2. **近端触发**：这次冲突前发生的可观察事实。
3. **维持机制**：用角色中立的抽象链路表示，例如 `A策略→B反应→A加码/撤离→B适应→原模式被强化`；实际链路必须完全来自当前评测输入。
4. **底层类别**：安全/权力控制、信任损伤、沟通技能不足、承诺可靠性、资源压力或核心目标不兼容。
5. **修复阻断点**：谁无法承认、谁不行动、哪项条件不可同时满足。
6. **竞争解释**：至少一个。
7. **可证伪预测**：如果机制判断正确，设立新规则后未来 2–4 周应观察到什么；什么结果会推翻它。

不要使用“A 就是缺乏安全感”“B 本质自私”作为机制。人格标签不可证伪，也不能直接指导行动。

## Report requirements by mode

报告开头必须写清：

- 模式：S / D / M，以及是否有 R 记录增强；
- 来源：谁作答、是否独立、是否有记录；
- 结论覆盖范围；
- 每个关键判断的证据强度；
- 固定量化摘要及其覆盖率、区间和模式限制；
- 交叉一致点、分歧点和可能改变结论的证据。

双/多视角增加公平性但不保证真相；单视角降低确定性但仍能帮助识别明确的不当行为和现实决策风险。
